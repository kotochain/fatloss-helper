## 最近这一轮发生了什么（v46，2026-10-27）

用户纠正了 v45 的方向：

> 逻辑应该是每次打开网页时都应该是最新版本，然后网页一直开着，有更新了主动在已打开的网页提示。

v45 做的是「打开旧版 → 顶部提示你去更新」—— 那是给错误兜底，**不该先把旧版塞给用户**。

**现在两条规则**（总账 R60 / R61）：

| 规则 | 谁负责 | 做法 |
|---|---|---|
| A. 每次打开都是最新版 | `sw.js` | 缓存策略从「先用缓存 + 后台更新」改成 **network-first** |
| B. 一直开着时发新版要提示 | `index.html` 内联脚本 | 启动 + 每 60 秒（仅可见）+ 切回前台 + 网络恢复 |

- 为什么之前必然旧版：stale-while-revalidate 命中缓存立刻返回，网络在后台跑 ——
  「打开的这一刻永远是上一次的版本」。不是提示没做好，是策略选错了。
- 网络优先的细节：`cache: 'no-cache'`（绕浏览器自己的 10 分钟 HTTP 缓存，有 ETag 时 304 很快）；
  断网（`onLine === false`）直接给缓存不等；弱网最多等 2 秒，超时给缓存、后台继续跑完。
- 「一直开着」：`check()` 有 `shown`（提示过就停）和 `checking`（防重入），
  60 秒轮询只在页面可见时跑。**横幅出现后不自动重载**，什么时候更新由用户点。
- 自检 `tools/update-check.mjs` 按新语义重写：① 发版后新开网页**直接是 v99**（不是「旧版 + 横幅」）；
  ② 页面保持打开再发 v100、触发 `visibilitychange` → 横幅出现且页面仍是 v99；③ 点横幅 → v100 且 localStorage 标记还在。
- 总账：R60 改写「打开就是最新版」，新增 R61「一直开着要提示」、R62「只清代码缓存不碰 localStorage」；
  62 条规则 / 61 条有测试。

**要接受的代价**：网络优先 = 每次打开多等一次网络往返（正常 1 秒内），换来「打开就是新版」。

## v45（2026-10-27）

用户真机反馈：**新开网页是上次的旧版本、顶部没有任何提示，手动刷新一下才变新版。**

- 根因两层：① PWA 先用缓存（当时策略如此），提示必须补上；
  ② 版本检查用 `fetch('sw.js', {cache:'no-store'})` **绕不过 GitHub Pages 的 CDN**（`max-age=600` + Fastly），
  读回旧版本号 → 判定「已是最新」→ 永远不提示。另外检查排在启动后 4 秒，用户早自己刷新了。
- 修法：`index.html` 内联一段版本自查（不依赖 app.js），`sw.js?ts=` 每次回源，
  页面一解析就跑；发现新版立刻亮顶部横幅「有新版本 vX，点这里更新（记录不会丢）」，
  点一下清代码缓存重载（不碰 localStorage）。app.js 提前到 1.2 秒，并让位给内联横幅。
- **v46 的修正**：这里只补了「提示」，没解决「打开本来就是旧版」—— v46 用 network-first 解决。

## v39（2026-10-27，issue #20）

用户在做 #20 时当场纠正了方向：**AI 就是用来估热量的，不该让用户补记填热量，更不该说「我没认出来」。**

真正的问题是：AI 请求失败/普通模式时，代码静默退回本地词表，再弹「这句话里的『佛跳墙』我没认出来」——
用户看到的是「AI 是个弱智」，而不是「AI 没连上」。三条铁律（已进总账 R55/R56）：

1. **AI 永远不说「不知道 / 没认出来」**：不确定就追问，但必须先给一版估算；
2. **用户可以回答「我也不知道」**：AI 必须自己按常见份量估，不能把问题推回给用户；
3. **只有普通模式/请求失败才用本地清单**：说清是「本地清单里没有」，并给「用 AI 重新解析」的出口。

v39 做了什么：

1. 草稿页新增「用 AI 重新解析这一句」：普通模式下先确认会发一次请求，确认后强制走 AI（跳过「我的食物」缓存）。
2. 删掉「我没认出来」的文案，换成「本地清单里没有「X」」+ 原因（普通模式 / AI 没连上）。
3. AI 追问独立成块：可以补一句重新估，也可以点「我也不知道，你按常见的估」——点了就不再追问。
4. 提示词写死「『不知道』只有用户有资格说」「questions 只问能帮到估算的细节」。
5. 「模型只给名字」的兜底（v35 已有）补上真界面断言，防止以后被改坏。

## 这次学到、别重犯的

- **「不知道」只有用户有资格说**：AI 的职责是估，不是把不确定推回给用户。界面文案不许出现「我没认出来」。
- **只有 AI 一种模式，没配就不发请求**：「说一句」只在密钥配好后走 AI；没配时直接说清并指路配置，不拿本地词表硬猜。
- **删掉一个功能，要连它的代码和测试一起删**：v42 删普通模式只删了入口，v43 才把没人调用的解析器清掉 ——
  中间那段时间，改食物别名的人还得多维护一份用不到的词库。
- **发布清单不许写死**：新增页面要问「它怎么上线」；`pages.yml` 现在是 `./*.html`，别再改回清单。
- **任何新测试只要读文件**，就要同步 `mutate-check` 的沙箱清单（沙箱必须等于仓库），否则会出现假红/假绿。
- **线上检查只证明「文件传对了」**，跑起来对不对必须用 `live-audit`；反过来 `live-audit` 也测不了「旧版本自救」，
  那条只能靠真机（#6）。
- 不要拿真实 AI 密钥做测试；密钥不在仓库（`data/ai-key.txt` 已被 `.gitignore` 挡住）。
- 文案红线：对使用者说「你」，不用第三人称；回顾/建议只陈述事实，不评判、不施压。
