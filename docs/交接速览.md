## 最近 24 小时发生了什么（v38，2026-10-26）

用户发来真机截图，上面是 **v30 以前**的旧行为（「AI 说库里没有 → 一条都没记上」）。
根因：早期 Service Worker **缓存优先、连 `sw.js` 都缓存** → 手机上永远读到旧版本号，更新提醒永远弹不出来，
装上一次就再也升不了级（缓存策略 v27 已修，但已经卡住的手机需要出路）。

v38 做了什么：

1. **30 天回顾**（issue #14 C）：成长页看记录天数/连续/蛋白达标/运动/体重趋势，只陈述事实、不评判。
2. **更新加固**：启动时发现新版且用户没动手 → 自动清缓存重载一次（每会话一次）；不能自动更新时挂**关不掉的横幅**；
   关于页加**强制更新**。
3. **自救页 `update.html`**：给已经卡住的手机用——注销旧 SW、清临时缓存、跳回新版，**不碰 localStorage**。
4. **用户原句进回归**：`direct-check` 三·四 用「早饭 喜茶苦巧咸酪碎银子少少甜」走真实界面，断言必须记上、

**发布后又抓到自己一个事故**：`update.html` 线上是 404 —— 发布脚本 `.github/workflows/pages.yml` 是写死的
文件名清单，漏了新页面。已修复（改成 `./*.html`），并加了三道防漏：版本测试盯着发布脚本、
`check-live` 把根目录 html 纳入逐字节比对、`live-audit` 新增「六·二」真线上打开自救页。
同一次还踩了「反向验证沙箱少拷文件 → 假红」，已在 `mutate-check` 修掉（沙箱拷根目录所有 html）。

## 这次学到、别重犯的

- **发布清单不许写死**：新增页面要问「它怎么上线」；`pages.yml` 现在是 `./*.html`，别再改回清单。
- **任何新测试只要读文件**，就要同步 `mutate-check` 的沙箱清单（沙箱必须等于仓库），否则会出现假红/假绿。
- **线上检查只证明「文件传对了」**，跑起来对不对必须用 `live-audit`；反过来 `live-audit` 也测不了「旧版本自救」，
  那条只能靠真机（列在 #6）。
- 不要拿真实 AI 密钥做测试；密钥不在仓库（`data/ai-key.txt` 已被 `.gitignore` 挡住）。
- 文案红线：对使用者说「你」，不用第三人称；回顾/建议只陈述事实，不评判、不施压。
