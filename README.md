# 减脂小助手

一个只给一个人用的小工具：记录每天吃了什么，算出热量和碳蛋脂比例，并给出「今天接下来怎么吃」和「一周练什么」的建议。

**数据全部存在使用者的手机上（浏览器本地存储），不联网、不上传、不需要注册。** 换手机或清缓存前记得在「体重」页导出一次存档。

---

## 〇、两个新增能力（2026-10-16）

### 1. 「说一句就记上」
不用在列表里翻找。在「记录」页直接写：

> 今天中午在食堂吃了碗牛肉面，加了个蛋

它会拆成「牛肉面 600 克 + 鸡蛋 1 个」，**先把结果给她看**（每条的克数都能直接改），确认后再记上。
份量说不清时会反问她（「大概多大一碗？小碗/普通碗/大碗」）。

**AI 接通前也能用**：内置的离线识别能认 100 多种常见说法（食堂打饭、盖饭、麻辣烫、火锅、饺子、
奶茶、外卖套餐……），认不出来的会明确说「这句我没认出来」，不会瞎猜一个数字。

### 2. 「今天练什么」跟着器械走
推荐页先问她今天有什么器械（跑步机 / 椭圆机 / 单车 / 划船机 / 登山机 / 徒手……），再出方案。

- 计划写的是**爬坡走，但跑步机被占了**——把「跑步机」取消勾选，方案会立刻变成椭圆机匀速，并写清「同样练心肺和腿臀，膝盖零冲击」。
- 想做的机器没空时，点「看替代方案」，会按她**实际能用的器械**给出替代动作，并说明为什么能替代（练到同一件事 + 强度对比）。
- 时间紧（20 分钟）时优先给间歇方案；时间宽裕（40 分钟以上）才推长时间中低强度。

力量训练按你说的先放着，现在全部是有氧 + 徒手循环。

## 一、怎么用起来（安卓手机）

### 第 1 步：在电脑上启动一次预览服务

```bash
node tools/serve.mjs
```

终端会打印两个地址，例如：

```
本机打开：  http://127.0.0.1:4173/
手机打开：  http://192.168.1.23:4173/   （手机需连同一个 Wi-Fi）
```

### 第 2 步：手机浏览器打开「手机打开」那个地址

用安卓自带的 Chrome 或 Edge 打开。第一次打开是「填写资料」页。

### 第 3 步：添加到主屏幕

Chrome 右上角「⋮」→「添加到主屏幕」/「安装应用」。之后桌面会出现图标，点开是全屏的，**和 App 基本一样**，而且断网也能用。

> 为什么不做成真正的安卓 App：那需要装安卓开发工具、签一个安装包、每次改动重新打包安装。这个网页版能立刻用、能随时改，以后真想上架应用商店，现在这套界面和算法可以原样搬进安装包里，不用重做。

### 第 3.5 步：接上 AI（可选，但推荐）

不接也能用（走离线识别）。接上之后，她怎么写都能听懂。

**直接在手机上配**（推荐，不用碰命令行）：

1. 她手机上打开工具 → 「记录」页 → 右上角 **「AI 设置」**
2. 选一家服务商（DeepSeek / 通义 / Kimi / 智谱 / 硅基流动 / OpenAI / 本地模型 / 自定义），
   接口地址和模型名会**自动填好**，也可以自己改（自定义端口、公司内网网关都行）
3. 去那家服务商后台创建 API Key，**粘贴到密钥框**（点服务商说明里的「去拿密钥 →」有直达链接）
4. 点「保存并测试连通」——成功会显示模型的实际回复；失败会给出中文原因（密钥错 / 余额不足 / 模型名不存在 / 连不上）

**安全设计（重点）**：密钥从手机发到**你这台电脑上的服务**，由电脑保存成 `~/.dsh/fatloss-ai.json`
（权限 600，只有本人可读，在项目目录之外）。**手机自己不保存密钥，服务端也从不把密钥回传**——
所以手机丢了、别人翻她手机，都拿不到你的 AI 账号。手机上看到的永远只有掩码（例如 `sk-te******cdef`）。

代价：AI 只在她手机和你电脑连同一个 Wi-Fi 时可用；出门在外自动退回离线识别，记录功能照常。

命令行也支持（给习惯终端的人，优先级低于手机上的设置）：

```bash
echo "sk-你的密钥" > ~/.dsh/fatloss-ai-key && chmod 600 ~/.dsh/fatloss-ai-key
```

### 第 4 步（可选）：不用电脑时也能打开

上面的地址只在开着电脑、同一个 Wi-Fi 时有效。想让她在外面也能打开，需要把这个文件夹放到一个免费的静态托管上（Cloudflare Pages / Vercel / GitHub Pages 都可以，都是免费额度）。这一步需要你注册一个账号，要的时候告诉我，我把文件准备好给你上传。

## 二、它到底算得准不准

诚实说明，分三层：

### 1. 算「她每天该吃多少」用的公式

- 基础代谢：Mifflin-St Jeor 公式（有体脂率时改用 Katch-McArdle），这是国际减重指南里最常用的公式，**误差一般 ±10%**。
- 每日消耗 = 基础代谢 × 活动量系数（久坐 1.2 ～ 非常高 1.9）。
- 热量缺口：按「每周减掉体重的 0.25% / 0.5% / 0.75%」换算，1 公斤脂肪按 7700 kcal 估算。
- 分配顺序是 **蛋白质 → 脂肪 → 碳水**：蛋白质 1.8 g/kg（80 kg 以上降到 1.6，且不超过总热量 35%）；脂肪 0.8~0.9 g/kg（不低于 0.6 g/kg 的安全线）；剩下的热量才是碳水，且碳水不低于 80 g。
  这个顺序很重要：反过来先定碳水，会算出「根本放不下」的脂肪目标（例如 100 kg 的人要 90 克脂肪），用户照着吃只会让脂肪永远差一半。

因为公式本身有 ±10% 的误差，**真正的校准靠体重趋势**：「体重」页会根据实际掉秤速度告诉你该多吃还是少吃（这个方法比任何公式都准）。

### 2. 内置的 108 种食物数据

- 主要参考《中国食物成分表》的常见条目和市售包装食品标签的典型值，对主食区分生熟。
- 每一条都做了自检：`蛋白质×4 + 脂肪×9 + 碳水×4` 必须和标称热量对得上（含酒精的除外），对不上就会被测试拦住。这一关已经抓出并修正了 30 条之前抄串的数据（例如「虾 93 kcal」却配了 2.8 g 碳水）。
- **炒菜、外卖、家常菜的误差最大**（同一道菜不同人放油差一倍），这几条只当参考。
- 少部分条目用的是更贴近日常吃到的口径，不完全是成分表的数：全脂牛奶按市售包装标签、鸡胸肉/红薯/西兰花/三文鱼按 USDA。两张表的口径差可达 ±20%，所以别当精确值用。
- **烹调油单独算**：餐单里会明确写出「全天烹调油 X 克，已算进总数」，避免出现「菜单不含油、提醒又让你加油」导致每天多吃一两百 kcal。
- **包装食品请照包装背面的营养成分表自己建**（「记录」页 → 新增自定义食物），那才是精确的。

### 3. 安全边界（代码里写死的，不是提示文字）

- 每天热量不低于基础代谢的 1.1 倍，且女生不低于 1200 kcal、男生不低于 1500 kcal；
- 每周减重不超过体重的 1%；
- 脂肪不低于 0.6 g/kg，碳水不低于 80 g；
- BMI 低于 18.5（偏瘦）时不给减脂缺口，直接劝退；目标体重低于 BMI 18.5 也会警告；
- 年龄填不满 18 岁会拒绝计算；
- 资料填错填漏时保存会被挡住（不会出现「身高清空 → 目标热量静默掉到 1200」这种事）。

### ⚠️ 不适用的情况

这个工具只做估算和记录，**不是医疗建议**。以下情况请先问医生，不要照这里的数字吃：

- 怀孕或哺乳期
- 有甲状腺、肾脏、糖尿病、进食障碍等疾病
- 正在服用影响体重的药物
- 未满 18 岁

## 三、功能

| 页面 | 做什么 |
| --- | --- |
| **今天** | 还能吃多少 kcal、三大营养素差多少、按餐列出吃了什么、今天的运动、以及一句「接下来怎么吃」 |
| **记录** | 搜索 107 种食物（支持俗称，如「地瓜」「美式」「奶茶」），支持「150克 / 2个 / 一小碗 / 半斤」这类写法；也有自定义食物 |
| **推荐** | 按她的热量和蛋白质目标算出每餐吃什么、吃多少克（含烹调油额度）；「今天练什么」按她当天能用的器械出有氧方案，并支持换器械的替代动作；另有走路目标 |
| **体重** | 记体重、看趋势图、按实际掉秤速度给出「该多吃还是少吃」的建议；导出/导入存档 |

几个设计上的取舍：

- **运动消耗只算一半**：手环给的消耗普遍偏高，所以只有一半计入「可以多吃」的额度，避免越练越胖。
- **份量都是整份/半份**：不会建议「吃 0.37 个鸡蛋」；配餐时主菜有热量上限，保证主食和蔬菜有位置。
- **餐单是起点不是规定**：换一套按钮可以换菜；「记入今天」之后按实际吃的改。
- **餐单会同时盯住热量、蛋白、脂肪、碳水四项**：只盯热量和蛋白的话，实测会出现「脂肪只有目标的一半」而用户不知道。

### 已知限制

- 食物数据是估算值，炒菜类误差最大；没有接入任何在线食物库（这是为了「不联网也能用」）。
- 脂肪目标在少数组合下只能达到 80% 左右：主食按「整份/半份」取整时会挤掉一点脂肪额度。要精确到克得自己称油。
- 餐单里的主食是「换算成米饭/燕麦的克数」，不是强制吃米饭——同类主食可以等量替换。
- 没有账号系统，所以只有一台设备能看到记录（多设备要手动导出/导入存档）。
- 修改 JS 后需要在手机上刷新两次才能拿到新版本（离线缓存机制），或把 `sw.js` 里的 `CACHE` 版本号加一。
- 没有做图片识别、条码扫描——这两件事需要联网服务和授权，暂时不做。
- AI 只在手机能和电脑连同一个 Wi-Fi 时可用（密钥不放手机上的代价）。出门在外自动退回离线识别。
- 配置只支持一个服务商（换家就是改一下设置）。如果以后想给多个人用，需要各自一份配置。
- 本地模型（Ollama）虽然免费且数据不出本机，但在普通笔记本上解析一句话可能要十几秒，体验不如云端。
- 离线识别是规则匹配，生僻说法认不出来（会明确说认不出来，不瞎猜）；接上 AI 后这个问题基本消失。
- 有氧动作的 METs 是通用值，个人的实际消耗会差 ±20%。
