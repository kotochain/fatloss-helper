# 减脂小助手

一个只给一个人用的小工具：记录每天吃了什么，算出热量和碳蛋脂比例，并给出「今天接下来怎么吃」和「一周练什么」的建议。

**数据全部存在使用者的手机上（浏览器本地存储），不联网、不上传、不需要注册。** 换手机或清缓存前记得在「体重」页导出一次存档。

---

## 一、怎么用起来（安卓手机）

### 第 1 步：在电脑上启动一次预览服务

```bash
node tools/serve.mjs
```

终端会打印两个地址，例如：

```
本机打开：  http://127.0.0.1:4173/
手机打开：  http://192.168.1.23:4173/   （手机需连同一个 Wi-Fi）
```

### 第 2 步：手机浏览器打开「手机打开」那个地址

用安卓自带的 Chrome 或 Edge 打开。第一次打开是「填写资料」页。

### 第 3 步：添加到主屏幕

Chrome 右上角「⋮」→「添加到主屏幕」/「安装应用」。之后桌面会出现图标，点开是全屏的，**和 App 基本一样**，而且断网也能用。

> 为什么不做成真正的安卓 App：那需要装安卓开发工具、签一个安装包、每次改动重新打包安装。这个网页版能立刻用、能随时改，以后真想上架应用商店，现在这套界面和算法可以原样搬进安装包里，不用重做。

### 第 4 步（可选）：不用电脑时也能打开

上面的地址只在开着电脑、同一个 Wi-Fi 时有效。想让她在外面也能打开，需要把这个文件夹放到一个免费的静态托管上（Cloudflare Pages / Vercel / GitHub Pages 都可以，都是免费额度）。这一步需要你注册一个账号，要的时候告诉我，我把文件准备好给你上传。

## 二、它到底算得准不准

诚实说明，分三层：

### 1. 算「她每天该吃多少」用的公式

- 基础代谢：Mifflin-St Jeor 公式（有体脂率时改用 Katch-McArdle），这是国际减重指南里最常用的公式，**误差一般 ±10%**。
- 每日消耗 = 基础代谢 × 活动量系数（久坐 1.2 ～ 非常高 1.9）。
- 热量缺口：按「每周减掉体重的 0.25% / 0.5% / 0.75%」换算，1 公斤脂肪按 7700 kcal 估算。
- 蛋白质 1.8 g/kg（减脂期）；脂肪不低于 0.6 g/kg；剩下的热量给碳水，碳水不低于 80 g。

因为公式本身有 ±10% 的误差，**真正的校准靠体重趋势**：「体重」页会根据实际掉秤速度告诉你该多吃还是少吃（这个方法比任何公式都准）。

### 2. 内置的 107 种食物数据

- 主要参考《中国食物成分表》的常见条目和市售包装食品标签的典型值，对主食区分生熟。
- 每一条都做了自检：`蛋白质×4 + 脂肪×9 + 碳水×4` 必须和标称热量对得上（含酒精的除外），对不上就会被测试拦住。这一关已经抓出并修正了 30 条之前抄串的数据（例如「虾 93 kcal」却配了 2.8 g 碳水）。
- **炒菜、外卖、家常菜的误差最大**（同一道菜不同人放油差一倍），这几条只当参考。
- **包装食品请照包装背面的营养成分表自己建**（「记录」页 → 新增自定义食物），那才是精确的。

### 3. 安全边界（代码里写死的，不是提示文字）

- 每天热量不低于基础代谢的 1.1 倍，且女生不低于 1200 kcal、男生不低于 1500 kcal；
- 每周减重不超过体重的 1%；
- 脂肪不低于 0.6 g/kg，碳水不低于 80 g；
- BMI 低于 18.5（偏瘦）时不给减脂缺口，直接劝退；
- 年龄填不满 18 岁会拒绝计算。

### ⚠️ 不适用的情况

这个工具只做估算和记录，**不是医疗建议**。以下情况请先问医生，不要照这里的数字吃：

- 怀孕或哺乳期
- 有甲状腺、肾脏、糖尿病、进食障碍等疾病
- 正在服用影响体重的药物
- 未满 18 岁

## 三、功能

| 页面 | 做什么 |
| --- | --- |
| **今天** | 还能吃多少 kcal、三大营养素差多少、按餐列出吃了什么、今天的运动、以及一句「接下来怎么吃」 |
| **记录** | 搜索 107 种食物（支持俗称，如「地瓜」「美式」「奶茶」），支持「150克 / 2个 / 一小碗 / 半斤」这类写法；也有自定义食物 |
| **推荐** | 按她的热量和蛋白质目标，直接算出每餐吃什么、吃多少克；下面是一周训练安排（徒手/哑铃，在家能做）和走路目标 |
| **体重** | 记体重、看趋势图、按实际掉秤速度给出「该多吃还是少吃」的建议；导出/导入存档 |

几个设计上的取舍：

- **运动消耗只算一半**：手环给的消耗普遍偏高，所以只有一半计入「可以多吃」的额度，避免越练越胖。
- **份量都是整份/半份**：不会建议「吃 0.37 个鸡蛋」；配餐时主菜有热量上限，保证主食和蔬菜有位置。
- **餐单是起点不是规定**：换一套按钮可以换菜；「记入今天」之后按实际吃的改。

## 四、给开发者的部分

```bash
node tools/serve.mjs          # 本地预览（会打印手机可访问的局域网地址）
npm test                      # 83 个自动化测试
node tools/mutate-check.mjs   # 反向验证：故意改坏 9 处代码，确认测试真的会失败
node tools/browser-check.mjs  # 无头 Chrome 真机尺寸自检（需先启动 serve），截图存 .selfcheck/
```

### 目录结构

```
index.html            单页入口，四个标签页
css/style.css         手机优先样式
js/calc.js            热量/营养素/安全边界计算（纯函数）
js/foods.js           食物数据库 + 数据自检 + 「一碗/半斤」解析
js/recommend.js       餐单生成（份量反推 + 缩份收尾）
js/exercise.js        运动库（METs）与一周训练模板
js/foodlog.js         搜索、按餐汇总（纯逻辑）
js/store.js           存档结构与读写逻辑（不直接碰 localStorage，方便测试）
js/app.js             界面与交互
tools/                本地服务、反向验证、浏览器自检
tests/                node:test 测试
```

### 已知限制

- 食物数据是估算值，炒菜类误差最大；没有接入任何在线食物库（这是为了「不联网也能用」）。
- 没有账号系统，所以只有一台设备能看到记录（多设备要手动导出/导入存档）。
- 修改 JS 后需要在手机上刷新两次才能拿到新版本（离线缓存机制），或把 `sw.js` 里的 `CACHE` 版本号加一。
- 没有做图片识别、条码扫描——这两件事需要联网服务和授权，暂时不做。
